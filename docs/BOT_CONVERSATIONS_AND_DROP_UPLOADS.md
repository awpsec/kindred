# Bot conversations and dropped files

General > Appearance > Separate bot conversations (default on) places bot-only workspace conversations under a collapsible Bot conversations section. The section is presentation only: turning it off does not add a human participant. Chat settings has a Bot-only conversation switch. The owner can inspect or intervene in these chats, but is presented to bots as an observer; the avatar stack no longer invents a human member.

New private-to-teammate handoff rooms and bot-created coordination groups are bot-only. chat_create accepts bot_only=false for an explicitly human-participating group. Migration marks only dedicated legacy team-* rooms without human-authored messages; it does not reclassify ordinary user-created rooms. Normal successful bot-only completions stay out of notifications; failures and requests needing attention still appear.

ask_question retains the source chat/topic identity but delivers its card to the requesting bot's owner DM. Answers resume there with source context, and prompts direct the bot to post the relevant outcome back to the group. Private question cards are not exported to other server-room members. Existing questions keep their original delivery destination. Group prompts identify the actual message sender and require named addressees and silence for non-contributions rather than public assignment deliberation. These are model instructions, not a guarantee that all model prose will comply.

Files can be dropped anywhere in the conversation, including the composer. They use the same draft upload queue as the attach button and paste, with five files/message and 8 MB/file limits. Text drags are untouched, drops outside the chat do not navigate the webview, and dialogs reject background drops. Tauri's native drop interception is disabled on the main chat webview so DOM file events can reach this queue.

Shared server chats now support uploads as well. Pending files belong to their uploader; sending binds them atomically to one room message. Only current room members can download sent files. Retries reuse the same send receipt, and files cannot be rebound to a second message. Room attachments are copied into participating bot profiles alongside the imported message, using the existing read_attachment and image-context paths. Unsent uploads expire after a day. Binary responses use attachment disposition, no-store and nosniff.

Validation includes Chromium/WebKit drop, sidebar and settings checks, shared file UI tests, membership/binding tests, private question routing and topic isolation, existing decision/chat/settings regressions, and Linux desktop cargo check. Native Finder/Explorer drop gestures still require native platform verification; no release was published.
