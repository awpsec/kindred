# Linux standalone recovery

For routine client upgrades, use [Linux client updates](LINUX_CLIENT_UPDATES.md).
The setup helper below repairs dependencies; it is not needed for each release.

The setup help panel ships in current desktop releases. The client-only mode and
Arch/CachyOS recovery improvements below are 0.50.0 changes; releases
remain subject to owner approval.

If standalone cannot start, Kindred checks Docker Engine, Compose v2 and daemon
access before unpacking the server bundle. Linux setup help opens with one
copyable terminal block. The person runs it as their normal desktop user;
Kindred never executes it or invokes sudo automatically. Clipboard denial leaves
the complete block selected for manual copying.

The block supports Ubuntu, Debian, Fedora, Arch Linux and the named CachyOS, EndeavourOS and Manjaro derivatives on x86_64 with systemd. It follows
the official [Ubuntu](https://docs.docker.com/engine/install/ubuntu/),
[Debian](https://docs.docker.com/engine/install/debian/) and
[Fedora](https://docs.docker.com/engine/install/fedora/) Docker repositories,
installs Compose, and starts the local engine where needed. Arch-based distributions use their own `docker` and `docker-compose` packages; the helper does not add an external repository or perform a database-only refresh. Conflicting container
packages, unavailable custom contexts, unsupported distributions and package
failures stop with an explanation. It does not remove existing container
software or delete Docker data.

Adding a user to the docker group grants administrator-level access. When group
membership is not active in the current session, the final instruction is to
**sign out of the desktop completely and sign back in**, then open Kindred and
retry standalone. A new terminal or `newgrp` does not refresh a desktop app
already running in the old session. See Docker's
[post-installation guidance](https://docs.docker.com/engine/install/linux-postinstall/).
The helper does not log the user out automatically.

## AppImage and menu integration

When launched from an AppImage, the block also installs the system WebKitGTK
runtime and makes a persistent copy under
`$XDG_DATA_HOME/kindred/linux/<AppImage SHA-256>` (default
`~/.local/share/kindred/linux/`). The compatibility executable has its bundled
library search path removed and launches directly using system libraries.
`APPDIR` still points to the extracted resources, including `standalone.zip`.
The original AppImage and existing Kindred account data are preserved.

It installs the icon into the user's hicolor icon directory and writes
`$XDG_DATA_HOME/applications/Kindred.desktop` with an absolute icon path and a
stable launcher. Desktop entry escaping follows the
[freedesktop Exec specification](https://specifications.freedesktop.org/desktop-entry/latest/exec-variables.html).
An existing extracted/native installation can use `--native /path/to/kindred-desktop`
to repair its menu entry without extracting another AppImage. Other manually
created menu files with different names are not removed.

The standalone script is `desktop/linux/setup.sh`. It accepts the AppImage path
as its optional first argument. After running it, close the old app and launch
Kindred from Applications. The original download still uses its original bundled
libraries; the Applications entry selects the persistent compatibility copy.

## Client-only audio repair

Use `bash desktop/linux/setup.sh --client` when connecting to an existing backend. This installs and verifies client/audio dependencies without checking Docker, starting services or changing group membership. No launcher is changed unless an AppImage or native executable path is also supplied:

```bash
bash desktop/linux/setup.sh --client /path/to/Kindred.AppImage
bash desktop/linux/setup.sh --client --native /path/to/system-linked/kindred-desktop
```

The AppImage form makes a private system-library compatibility copy and preserves the original. The native form is for an executable already using the host libraries. Generated launchers clear GStreamer plugin paths, scanner and registry overrides so the host libraries use matching host plugins. If any required audio plugin is unavailable, setup stops before writing a launcher.

On Arch/CachyOS, `gst-plugins-good` contains both `autoaudiosink` and `pulsesink`; `gst-plugin-pipewire` alone does not provide them. Install matching distribution packages rather than restoring arbitrarily disabled bundled libraries. A manually converted `Applications/Kindred.AppDir` with `usr/lib/gstreamer-1.0` linked to the host is not an untouched AppImage and is not the layout generated by this helper. Repairing its missing host plugins preserves that conversion. If using Arch, keep the system updated normally before installing packages; the helper does not perform a system upgrade.

## Window resizing, reading size and settings

The Linux main window keeps GTK's decorated, resizable frame but replaces the
separate system title row with a zero-height title widget. Theme-matched window
controls live in Kindred's existing conversation header; the sidebar and chat
headers support dragging and double-click maximize. Its Accounts and Desktop
permissions pages retain normal native frames and open as separate windows. This avoids WebKitGTK's additional-webview layout
shrinking the main app. Windows and macOS keep their existing window behavior.

Linux defaults to 115% text size (about one point smaller than the previous
125% default). Change **Settings → General → Text size** to
100%, 115%, 125% or 150%. This preference is saved on the device for the current
app origin. It enlarges text without zooming the whole window or changing native
webview coordinates. Bundled Accounts and permission windows also default to
115%; their native app origin has its own stored preference. Explicitly saved
sizes, including 125%, are preserved. Windows and macOS still default to 100%.

An unreleased Linux debug binary compiled successfully and ran in an isolated
Debian 13/WebKitGTK/Xvfb/Openbox desktop. A real pointer drag on its lower-right
frame resized the window from 1320×860 to 1171×770. Opening Desktop permissions
created a second window while the main window remained 1171×770, with its settings
layout intact. That earlier build's screenshots confirmed readable text, its
then-current 125% default and native
window controls. Local permissions remained Off; no actual mailbox or bot computer
was used. Edge and WebKit fixtures cover text-size persistence, narrow layouts and
the Linux settings invocation without embedded child bounds. This is not yet
acceptance on the owner's desktop environment or GPU.

## Setup verification and limits

- Twelve Linux command-fixture tests cover fresh Engine/Compose installation,
  group membership versus the current session, repeat use after sign-in,
  Compose-only repair, conflicting packages, unsupported distributions,
  package failure, custom context failure, Fedora/Arch command selection, client-only dependency repair, missing plugin detection, and clearing stale GStreamer paths in the generated launcher.
- The native Rust helper's test checks shell quoting, literal script content,
  native fallback arguments and LF line endings. Native probes have bounded
  waits and never elevate privileges.
- Edge and bundled WebKit exercise the actual onboarding HTML/JS with fixture
  IPC: copy without execution, clipboard fallback, one setup attempt on double
  click, error/retry/success, sign-out guidance, and narrow layout.
- The released AppImage was installed as an unprivileged user in an isolated
  Ubuntu 22.04/Xvfb container. Its generated desktop entry passed
  `desktop-file-validate` and launched through `gio launch` with spaces, `$` and
  `%` in the install path. The icon existed, `ldd` resolved system libraries,
  Accounts rendered, and the Standalone button found the bundled Compose file.
  Re-running the installer succeeded. Docker calls in this smoke test were
  simulated; no real server or guest computer was started.

Fresh OS package installation, desktop sign-out/sign-in and GPU behavior on the
owner's laptop remain machine-specific acceptance work. This lane did not build
or publish new desktop packages; the existing AppImage validated the installer,
while the new UI and native helper were checked separately.

The integrated Linux header is a source change awaiting packaging. Browser fixtures verify header geometry and control dispatch; a GTK/Xvfb fixture verifies the title widget occupies only one pixel while decorated/resizable flags remain enabled. These checks do not replace packaged-app verification of dragging and edge/corner resizing on X11 and Wayland.
